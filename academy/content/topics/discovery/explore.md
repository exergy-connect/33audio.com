## One source, many readers

People find parts through Google and Bing. Increasingly they also ask ChatGPT, Claude, or Perplexity, which read the web through their own crawlers. Each reader wants a different format, and all of them should agree. The shop generates every format from the same parsed catalog in one build, so they cannot drift apart.

::: diagram discovery-surfaces

| Surface | Reader | Generated by |
| --- | --- | --- |
| Part pages with Product, Offer, FAQPage, BreadcrumbList JSON-LD | Search engines, rich results | `catalog/build.py` |
| `llms.txt`, `llms-full.txt` | LLM agents and AI search | `catalog/llm_pages.py` |
| `catalog.json`, `catalog.md` | Agents and scripts | `catalog/llm_pages.py` |
| `sitemap.xml`, `robots.txt` | All crawlers | `catalog/build.py`, `catalog/llm_pages.py` |
| `schema/catalog.schema.json`, `context.jsonld`, `vocab.jsonld` | Validators and linked-data tools | xYang via `catalog/schema.py` |

## The xYang ontology

`model/audio33-catalog.yang` describes the public catalog in YANG 1.1. Custom extensions map nodes to schema.org classes and properties, and to Wikidata items such as resistor (Q5321) and ohm (Q47083):

::: embed model/audio33-catalog.yang "list parts {"

[xYang](https://github.com/exergy-connect/xYang) turns the model into a JSON Schema 2020-12 document, a JSON-LD context, and a vocabulary. `catalog.json` points at both with `$schema` and `@context`, and `python -m catalog schema --check` fails CI when the catalog, the schema, and the model disagree.

## Trade-offs

| Decision | Benefit | Cost |
| --- | --- | --- |
| Allow AI crawlers | The shop can be cited in AI answers, with links | Content can be used for model training; revisit with AI Crawl Control or pay per crawl if that matters |
| Generate every format in one build | No drift between HTML, JSON-LD, llms.txt, and catalog.json | The generator is more code than a hand-written file |
| Own YANG model plus schema.org | Strict validation and a precise vocabulary | Two vocabularies to keep aligned; the extensions carry the mapping |
| Static files, not an API | Cacheable, crawlable, free to serve | Updates wait for the daily rebuild |

## Measuring discovery

::: chart crawler-hits

This chart requests live crawler analytics when the page opens. Use **Refresh live analytics** to query again; results are cached for 60 seconds. It shows the last 24 hours of user-agent matches, which are not verified crawler identities. Cloudflare analytics may be delayed and sampled. If live analytics is unavailable, the saved chart stays visible with its provenance badge.

The shop records successful crawler GET/HEAD requests through Pages Functions middleware into the `caddock_crawlers` Analytics Engine dataset. This works on `33audio-com.pages.dev` without a custom domain or zone ID. Recording starts after deployment; historical traffic is unavailable. Preview hostnames are excluded. Only crawler labels, surface categories, and the configured shop hostname are stored; raw user agents and visitor IPs are not stored.

To enable it, deploy the shop with the `CRAWLER_EVENTS` Analytics Engine binding in the root `wrangler.toml`. In the Academy, set `CF_ACCOUNT_ID` in `academy/wrangler.toml` and run `npx wrangler secret put ANALYTICS_API_TOKEN` from `academy/`, using an Account Analytics Read token for the same Cloudflare account. Redeploy the Academy Worker. Find the account ID in the Cloudflare dashboard under Workers & Pages. Both deployments default to `CRAWLER_HOST = "33audio-com.pages.dev"`; if the shop hostname changes, configure the same value in both projects. The token stays in the Worker; browsers receive only aggregate counts.

Only discovery files, part pages, and existing API routes invoke Pages Functions; other static assets bypass them via the generated `_routes.json`. These tracked requests use Pages Functions invocations. If no crawler events have yet created the dataset, the live query may be unavailable until the first event is recorded.

The endpoint is `GET /api/crawler-analytics`. Its JSON includes counts, the query window, source, and collection timestamp; no rebuild is needed for a refresh.
